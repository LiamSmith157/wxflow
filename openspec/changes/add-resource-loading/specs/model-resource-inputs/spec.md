# Spec Delta

## Purpose

定义 LLM 和 Agent 节点如何把资源库中的资源作为本次模型调用的输入：图片作为视觉输入，文档作为文本上下文，以及它与对话记忆、执行记录的关系。

## ADDED Requirements

### Requirement: LLM 和 Agent 节点可以附加资源

LLM 和 Agent 节点 SHALL 提供"附加资源"参数，可以添加多个资源。每一项 SHALL 可以从下拉中选择当前工作区的图片或文档资源（不列出视频），也可以输入 `res://name/<名称>`（可以含变量）。该参数 SHALL NOT 接受本地绝对路径或 URL。不添加任何资源时，节点行为 SHALL 与本 change 之前一致。

#### Scenario: 下拉不列出视频

-   **WHEN** 资源库中有图片、视频和 pdf，用户打开 LLM 节点附加资源的下拉
-   **THEN** 下拉中有图片和 pdf，没有视频

#### Scenario: 未附加资源

-   **WHEN** 一个资源库上线前保存的 LLM 节点运行
-   **THEN** 发给模型的消息与本 change 之前相同

### Requirement: 附加的图片作为视觉输入

附加的图片资源 SHALL 作为图片内容发给模型，与本次调用的用户输入放在同一轮。所选模型没有开启图片输入时，节点 SHALL 失败，提示需要在模型设置中开启图片输入，而不是静默忽略图片。

#### Scenario: 让模型看图回答

-   **WHEN** LLM 节点附加了图片资源 `海报-北京`，输入消息为"海报上的活动日期是哪天？"，模型已开启图片输入
-   **THEN** 模型收到该图片和这条消息，回答基于图片内容

#### Scenario: 模型未开启图片输入

-   **WHEN** LLM 节点附加了图片资源，所选模型没有开启图片输入
-   **THEN** 节点失败，提示在模型设置中开启图片输入

### Requirement: 附加的文档作为文本上下文

附加的文档资源 SHALL 按 `resource-loading` 的规则提取文本，作为本次调用的上下文发给模型，每份文档前 SHALL 标明资源名称。任一文档无法提取文本时，节点 SHALL 失败，规则同 `resource-loading`。

#### Scenario: 根据产品手册回答

-   **WHEN** Agent 节点附加了 pdf 资源 `产品手册`，用户问"保修期多久？"
-   **THEN** 模型收到标明"产品手册"的文档文本和这条问题，回答基于手册内容

#### Scenario: 附加的文档无法提取文本

-   **WHEN** LLM 节点附加的资源中有一个 zip 文件
-   **THEN** 节点失败，错误信息给出该资源名称，并说明无法提取文本

### Requirement: 附加资源与对话记忆

附加资源的内容 SHALL 只用于本次模型调用，SHALL NOT 写入对话记忆或会话的聊天记录；同一会话的后续调用 SHALL 重新载入节点上配置的资源，因此替换资源文件后，下一次调用 SHALL 使用新文件。

#### Scenario: 多轮对话

-   **WHEN** 开启了记忆的 LLM 节点附加了 `产品手册`，同一会话中用户连续提问两次
-   **THEN** 两次调用都收到手册内容，对话记忆中只有用户问题和模型回答，没有手册全文

#### Scenario: 替换资源后

-   **WHEN** 用户替换了 `产品手册` 的文件，同一会话中再提问一次
-   **THEN** 这次调用收到的是新文件的文本

### Requirement: 附加资源的执行记录

LLM 和 Agent 节点的执行记录 SHALL 列出本次附加的资源名称和类型，SHALL NOT 保存图片的 base64 内容或文档的全文。

#### Scenario: 查看执行记录

-   **WHEN** 附加了一张图片和一份 pdf 的 LLM 节点运行后，用户在 Executions 中查看该节点
-   **THEN** 记录中列出这两个资源的名称和类型，没有 base64 内容和 pdf 全文
