# Design

## Context

节点定义写在 `packages/components/nodes/**`,由 server 的节点 API 原样返回,UI 在 `AddNodes`、`NodeInputHandler`、`DocStoreInputHandler`、`ArrayRenderer` 和下拉组件中直接渲染 `label`、`description`、`placeholder`、`options[].label` 等字段。`add-i18n-zh-cn` 已提供 i18next 基础设施,以及以英文原文为 key 的 `dynamic` 命名空间和 `td()`。用已构建的 `packages/components/dist/nodes` 实例化全部节点后,抽取到 2828 条去重文案,其中 1789 条不超过 3 个词,260 条超过 80 字符。

## Goals / Non-Goals

**Goals:**

-   在不改动 components/server/agentflow 的前提下,让节点目录文案随界面语言显示。
-   文案可以分批翻译,未翻译的随时回退英文。
-   翻译表可以随节点定义的变化用脚本检查和更新。

**Non-Goals:**

-   不让节点定义本身携带多语言字段。
-   不翻译 `name`、选项取值、示例值和服务端返回的动态数据(如 load method 返回的模型列表)。

## Decisions

-   **独立的 `nodes` 命名空间,以英文原文为 key。** 与 `dynamic` 同样的做法:key 是英文原文,`keySeparator`/`nsSeparator` 关闭,缺失时返回原文。不并入 `dynamic` 是因为体积大(约 9 万字符)且由脚本维护,与手写的界面文案分开更清楚。备选:按节点名分层(`nodes.chatOpenAI.label`)。放弃是因为同一个文案(如 `Temperature`、`Model Name`)在很多节点重复,按原文去重后只需翻译一次,也不用在 UI 里知道节点标识。
-   **在渲染处翻译,不在 API 边界翻译。** 在 API 响应处翻译会让语言切换需要重新请求,并且让后续用 `label` 做比较、搜索的代码拿到翻译后的值。渲染处翻译即时响应语言切换,数据保持原样。备选:在 `api/nodes.js` 里转换响应。放弃,理由同上。
-   **`tn(text)` 加 `useNodeT()` hook。** `tn` 与 `td` 同形(查表、缺失回退原文);组件通过 hook 订阅语言变化。节点列表搜索仍对英文原文和翻译后文本都做匹配,方便中英文用户搜索。
-   **同一文案的上下文差异不处理。** 以原文为 key 意味着同一英文文案只有一个译法。首版不支持按上下文区分译法,先接受单一译法,并在覆盖率报告中列出歧义词供之后处理。
-   **只翻译显示文本。** 下拉选项的取值使用 `name`,UI 中选项的 `label` 只用于显示;实现时在每个接入点核对没有用 `label` 做取值、比较或持久化。
-   **脚本维护翻译表。** `extract-nodes` 脚本实例化 `dist/nodes` 下全部节点,输出按类别分组的清单;`nodes-coverage` 用清单对比 `nodes.json`,报告覆盖率和多余条目。`en/nodes.json` 保持空对象(原文即 key,缺失回退即显示原文);`zh-CN/nodes.json` 由初稿翻译产生后再脚本校验。
-   **品牌、模型名与代码标识用规则保留英文。** 抽取脚本给出候选(含大写缩写、版本号、点号、斜杠和 `$`/`{}` 的文案),这些条目在 `zh-CN` 中与英文相同或不收录,由覆盖率检查豁免。

## Risks / Trade-offs

-   [用 `label` 当取值的代码被翻译破坏] → 接入点逐一核对,并加入"中文下选择选项后保存的值与英文一致"的测试。
-   [同词多义导致个别译文不准] → 初版接受单一译法,覆盖率报告列出出现在多种类别的同一原文,之后按需处理。
-   [翻译表体积增大主包] → 先静态打包并记录构建后体积变化;若超出预期再改为切换到中文时按需加载。
-   [节点定义更新后翻译过期] → 覆盖率检查列出新增的未翻译文案和多余条目,过期条目只会让对应文案回退英文,不会出错。
-   [机器翻译质量不一] → 按已确定的术语表统一术语;不做产品评审是已确认的决定,上线后按反馈修订 `nodes.json`。
-   [描述中含 HTML 或 Markdown 片段] → 抽取脚本标出含标签或链接的描述,翻译时保留标记原样。

## Migration Plan

-   没有数据迁移。分批合入:基础设施与第一批文案先合入,第二批后补;每批独立可回滚,回滚只会使文案回退为英文。
-   `nodes.json` 缺失条目的回退是唯一的兼容手段,不需要开关。

## Open Questions

-   `nodes.json` 是否最终改为按语言按需加载,取决于第一批合入后的构建体积。
